## 已发现的 BUG（都已修复）

### 1. 承诺抽取过度推理（v0.9.2 修复）
说"我明天下午要开会，可能很晚" → 抽出：
> "他明天下午要开会，可能很晚，**今晚和明天可能都没法陪我**"

后半句是模型自己推理出来的，原话里没有。后果是她会记着一个没人做过的承诺。
**修法**：提示词标准从"她会在意的事"收紧为"**他明确说出的约定**"，并加多个反例 + "严禁推理严禁补充"。

### 2. 重复承诺不去重（v0.9.2 修复）
连说 3 次"明天带你去吃火锅" → 库里 3 条，她会连着几天提同一件事。
**修法**：抽取后用本地 embedding 查相似 pending，命中就升级权重 + 重置冷却，不新建。

### 3. 去重阈值的陷阱（v0.9.2 写进代码注释）

实测中文短句的 embedding 相似度：
```
"他说明天带我去吃火锅" / "他答应明天带我去吃火锅"  -> 0.998  (同一件事)
"他说明天带我去吃火锅" / "他明天带我去看电影"      -> 0.887  (不同的事！)
"他答应周末陪我去海边看日出" / "他说周末去看日出"  -> 0.813  (同一件事，换说法)
```
句子结构相同、只有动作不同时相似度虚高。
**阈值必须 ≥ 0.95**，定 0.85 会把"吃火锅"和"看电影"误判成同一件事。

### 4. 🔴 数据库并发锁死（v0.10.0 修复，最严重）

测试时所有写操作 500：`sqlite3.OperationalError: database is locked`

`db.connect()` 原来是**全局共享一个连接**（`check_same_thread=False`）。
这个参数只是关掉检查，SQLite 连接对象**本身不是线程安全的**。
后台任务（留言/场景/承诺/原文索引）并发写时内部状态互相干扰，
一个事务卡住 → 全部报 locked。

**这是项目原有隐患**（`_lock` 定义了却从未使用），加留言功能后并发升高才引爆。

**修法**：`connect()` 改成 thread-local（每线程独立连接）+ `busy_timeout` 5s→15s。
验证：30 并发写全成功、60 混合请求无错误（`test_8`）。

**教训**：`check_same_thread=False` ≠ 线程安全。SQLite 要么每线程一个连接，
要么老老实实加锁——没有第三条路。
