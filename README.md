# AI Companion

AI 语音伴侣系统 - 单服务架构版本

## 功能

- **引导页入口**：选角色、选对话、选新建，点进去才进聊天
- **引导建对话**：一次引导 = 一个新剧本（世界 + 你是谁 + 主要人物 + 关系），
  建完直接落成一个可玩的对话，回引导页点卡片就能开始角色扮演
- 角色人格库（多角色共存，人设存数据库）
- 世界模板（可复用、可复制改造）
- 一句话 AI 生成全套人设（快速建对话）
- 多会话聊天
- 多 LLM 后端支持（DeepSeek、智谱、Ollama、通义、百度、Agnes）
- 记忆系统
- 人物关系管理
- TTS 语音播报
- 后台管理

## 访问

浏览器打开 **http://127.0.0.1:8877**（端口以 `.env` 的 `PORT` 为准）

打开的是**引导页**，选个人或选段对话点进去就是聊天页。

| 地址 | 页面 |
|---|---|
| `/` | 引导页（应用入口） |
| `/chat` | 聊天页 |
| `/chat?s=<会话ID>` | 直接进指定对话 |
| `/admin` | 后台管理 |

### 建一次引导会得到什么

引导问五件事：**世界** → **你是谁** → **主要人物** → **你们的关系** → **还有谁**。
确认后一次落成两样东西：

1. 主要人物的完整人格（性格、规则、语气样例）——存 `personas` 表
2. 一个绑定这个人格的对话——存 `sessions` 表，标题「和XX的对话」

所以建完不用再做别的，回引导页点那张卡片就能开聊。
没显式选世界时，会自动继承当前主角的世界（不会建出不属于任何世界的孤立角色）。

> 「设为主角」不在引导里——建对话不该顺手把别人的主角位抢走。
> 要换主角去引导页角色卡上点「设为主角」。

> ⚠️ 不要用 `localhost`：本机代理栈会拦截 IPv6 回环（`::1`），
> 每次新连接要等满 2 秒才 fallback 到 IPv4。`127.0.0.1` 直连只要 13ms。

## 安全说明（2026-10-13 加固）

- 服务默认只绑本机（`HOST=127.0.0.1`）。需要手机/局域网设备访问时，
  在 `.env` 写 `HOST=0.0.0.0`，**并强烈建议同时设置 `ACCESS_TOKEN`**
  （设置后所有请求要带 `?token=xxx`，浏览器首次带一次即记住）
- `/api/llms` 接口返回的 API Key 已脱敏（`sk-xxxx***xxxx`），防止同网设备窃取

## 改提示词

**所有提示词只住 `prompts/` 文件夹**（v0.16.0 起），按域分文件，改完**立即生效，不用重启**：

| 文件 | 管什么 | key |
|---|---|---|
| `prompts/functional.json` | 功能型：长度模式、摘要、状态卡、人物/关系检测 | `length_modes.*`、`summary*`、`state_card`、`detect_*` |
| `prompts/chat.json` | 聊天注入：群像规则、视角扮演两版、钦点记忆标题 | `chat.group_rules`、`chat.pov_full`、`chat.pov_lite`、`chat.pin_memory` |
| `prompts/tasks.json` | 后台任务：场景提取、承诺抽取、主动留言（含各自 system） | `tasks.scene_*`、`tasks.loops_*`、`tasks.proactive_*` |
| `prompts/onboarding.json` | 引导：五层文案、设计师人设、预览 | `onboarding.layer_1..5`、`onboarding.guider`、`onboarding.preview` |
| `prompts/memory.json` | 记忆注入段标题 | `memory.chunk_header`、`memory.saved_header` |

**唯一例外**：`onboarding.py` 的 `_GENERATE_PROMPT`（引导落库前的人设生成，内含大段
JSON 格式示例）留在代码里，改它需要重启服务。除此之外代码里不该再有任何提示词文案——
代码里的同名常量只是「default 兜底」（JSON 文件缺失/损坏时才生效）。

文案里可以用占位符，值由调用方传入；`{{PROTAGONIST}}` `{{TRAITS}}` `{{USER_NAME}}`
`{{RELATION}}` 这四个从人格库自动取（换角色跟着变）。占位符拼错不会无声坏掉：
服务日志会警告「用了 {{X}} 但调用方没传该变量」。

自检：`python tools/check_prompts.py`（查死配置 / 硬编码角色名 / 占位符未接线）。

**角色人格**（性格、说话方式、规则、语气样例）在数据库 `personas` 表，
用引导页 `/` 管理，不要手改。

### 人设生效源：DB 是唯一生效源，JSON 只是种子（v0.15.3 明确）

项目里有三处跟人设有关，名分如下：

| 位置 | 身份 | 说明 |
|---|---|---|
| 数据库 `personas` 表 | **唯一生效源** | 一切写入口（API / 引导 / 保存）只写这里 |
| `persona_local.json` / `persona_anchor.json` | 种子 / 备份基线 | 仅人格库为空时兜底读取，防止服务崩；**改它对已入库角色无效** |
| `backups/personas_*.json` | 自动备份 | 每次种子导入前自动生成 |

相关接口：

- `GET /api/personas/active` —— 当前生效人设 + 来源（`db` 正常 / `file` 库空兜底 / `none` 啥都没有）
- `POST /api/personas/import-seed` —— 把种子 JSON 写进人格库，**导入前自动全量备份**；
  已有主角就地覆盖更新（id 和数据库专属字段保留），库空则新建

> 历史教训（2026-10-20）：曾出现「改完 JSON 人设、实测回复毫无变化」的怪事，
> 根因就是双源——改了不生效的文件。现在兜底读取会打 warning 日志，
> 引导页人设面板在库空时也会显示警告横幅，不会再静默。

## 两种记忆的区别

| | 指令 | 存哪 | 怎么进上下文 | 什么时候会想起 |
|---|---|---|---|---|
| **钦点记忆** | `记住：X`<br>`帮我记住X` / `别忘了：X` | `pinned_memories` | **每轮全量注入**，不走检索 | 一直在，100% 可靠 |
| **保存记忆** | `保存记忆：X` | `memories` | **语义检索**，相似度 ≥0.55 才注入 | 聊到相关话题才想起 |

选哪个：**重要的、必须不忘的用「记住」**；**想存但不用每次都在的用「保存记忆」**。

钦点记忆会自动归槽（约定安排 / 雷区偏好 / 关系共识 / 人物印象），
相似度 ≥0.95 的重复条目会自动替换旧的，不会越堆越多。

## 换 embedding 模型

当前用 `BAAI/bge-small-zh-v1.5`（512 维，**中文专用**），放在 `E:\bus\models\embedding-zh`。

> ⚠️ **不要换回`all-MiniLM-L6-v2`**——那是纯英文模型，
> 实测中文丢失率 70%（满屏 `[UNK]`），记忆检索会**静默失准**：
> 服务不报错、接口正常，只是悄悄检索不准，极难发现。

换模型步骤：

```bash
# 1. 把新模型放到 E:\bus\models\embedding-zh（或设环境变量 EMBEDDING_MODEL_PATH）
python tools/rebuild_vectors.py --check    # 先体检：中文识别率 + 维度是否匹配
python tools/rebuild_vectors.py           # 再重建全部向量（自动备份数据库）
```

**换完模型必须重建向量**——新旧向量来自不同语义空间，维度不同混在一起比较毫无意义。

体检工具会直接告诉你中文认不认得：

```
token 总数: 32  [UNK]: 0  丢失率: 0.0%
结论: ✓ 认得中文
```

> ⚠️ `prompts.json` 里别写死角色名。写死了换个角色就失效——
> 而且因为这个文件优先于代码里的兜底文案，写错时不会报错、只会悄悄用错的那份。
> 改完可以跑 `python tools/check_prompts.py` 自检（查死配置 / 硬编码角色名 / 占位符未接线）。
