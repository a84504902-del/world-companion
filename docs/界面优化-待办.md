## 1. 消息时间戳改 hover 显示

**问题**：96 条消息就有 96 个灰色时间戳挂在下面，视觉很密。
加了跨天分隔线（`9月14日` / `3 小时后`）之后，逐条时间戳的价值已经下降。

**做法**：
- `.message-time` 默认 `opacity: 0`，`.message:hover .message-time { opacity: 1 }`
- 加 `transition: opacity .15s` 让出现不生硬
- 副作用：移动端/触屏看不到时间——本项目是桌面用，可接受

**涉及**：`static/css/style.css`（`.message-time` 在 334 行附近）

---

## 2. 输入框自适应高度

**问题**：`#messageInput` 是 `rows="1"` 的 textarea，打长句子时不长高，只能内部滚动。

**做法**：
- 监听 `input` 事件，把 `style.height` 设为 `auto` 再设为 `scrollHeight + 'px'`
- 设上限（比如 160px），超过才出滚动条
- 发送后重置回单行高度

**涉及**：`static/js/app.js` 的 `setupTextarea()`、`static/css/style.css`

---

## 3. 「正在输入」指示

**问题**：DeepSeek 首字延迟 1–3 秒，这段空白期用户不知道是在加载还是卡住了。
真人聊天时你能看见对方在打字，这个反馈很关键。

**做法**：
- 发送后、首个 token 到达前，在消息区显示一个「夏雪正在输入…」的占位
- 首个 `content` 事件到达时移除，换成真正的流式气泡
- 样式可以很淡（`--text-muted`），不要抢戏

**涉及**：`static/js/chat.js` 的 `sendMessage()` / `createStreamingMessage()`

## 4. 长会话分页渲染（预防性）

**问题**：`history_handler` 返回**全部**消息，前端 `innerHTML` 全量替换。
现在 124 条没事，但长期玩到几千条会明显卡。

**做法**：
- 前端只渲染最近 200 条
- 往上滚到顶时加载更早的（前端 slice 即可，后端已有全量数据）
- 或用 `IntersectionObserver` 做无限滚动

**涉及**：`static/js/chat.js` 的 `renderMessages()`

**⚠️ 现在不做也行**，但要记得迟早要处理。

## A. 场景状态卡（新功能）

**目的**：状态条显示「她在哪、在干嘛」，这是"世界感"的关键一块。
现在状态条只有时间和承诺，缺"此刻她在做什么"。

**做法**：
- 扩充已有的 `session_states` 表（覆盖式写入，本来就是干这个的）：
  - 用户在哪（家 / 外面 / 公司）
  - 她在哪、在干嘛
  - 当前场景
- 识别「我出门了 / 我回来了 / 我先睡了」这类边界句 → 写进状态
- `/api/status` 返回，前端状态条显示

---

## B. 她主动发消息（新功能，原始痛点）

**目的**：你不在的时候她给你发消息，回来时像真人女友那样看到几条留言。
**这是整个项目最初那个痛点的终点。**

**依赖**：A（场景状态）+ 已有的剧情时钟（`timeflow`）

**做法**：
- 会话开始时结算一次（`timeflow.settle` 已在做）→ 若间隔超过阈值，生成她在间隙里发的 1–3 条消息
- 消息带时间戳写进历史，视觉上跟正常对话区分开（更淡、带时间）
- 走 agnes（免费）或 DeepSeek
