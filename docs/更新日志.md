## v0.11.30 · 2026-09-20 20:55 · ⭐ 多角色扮演（视角切换）

**用户需求**：对话中想切到其他角色视角，但被人设锚点拦住（三条"只扮演夏雪"铁令）。

### 设计
- **指令**：`切换视角：沈青` / `扮演：沈青`（名字必须在人物表中）；`切回夏雪` 或 `切换视角：夏雪` 返回
- **动态人设**：actor ≠ 夏雪时，跳过 persona_anchor（夏雪专属），从**人物卡动态生成**角色人设：
  身份/性格/说话方式/爱好/雷区 + 通用规则（第一人称、纯对话、禁怯懦、成人直白、称呼按【人物称呼】段、4-8句）
- **历史提示**：注入"历史里 assistant 发言属于夏雪视角，不是你说过的"——防止角色把夏雪的话当自己的
- **群像自适应**：群像规则里"夏雪是唯一主角"自动替换为当前角色（llm.py 按 actor 参数 replace）
- **存储**：sessions 表加 actor 列（迁移幂等），每个会话独立记忆自己的视角

**自测**：切换存取、动态人设构建、群像规则替换，端到端通过。
**生效**：需重启服务。**文件**：`db.py`、`routes/chat.py`、`llm.py`

## v0.11.28 · 2026-09-18 22:55 · 修"人物配置点不动"

**用户反馈**：点"人物配置导入导出"没反应、不弹窗。

### 根因
1. **浏览器缓存旧 JS**：挂载表里明明有 openPersonConfigModal，但浏览器还在跑缓存的旧 app.js
   → onclick 找不到函数静默报错
2. **静态资源无缓存控制**：`add_static` 没禁缓存，每次改前端都可能"改了没生效"
3. 顺带发现：文件导入的 onchange 没传参，选了文件会报错

### 修复
1. **`app.py` 加 `no_cache_frontend` 中间件**：/static 和主页响应一律
   `Cache-Control: no-cache, no-store, must-revalidate` —— **以后改前端刷新即生效，永久根治**
2. `importFromFile` 改为自己按 id 找元素（不依赖 onchange 传参）

**生效**：重启服务 + 浏览器 Ctrl+F5（最后一次需要强刷，以后不用了）。
**文件**：`app.py`、`static/js/memory.js`

### 怎么"不画线还能分隔"

答案：**靠"缝 + 明度 + 形状"，不靠线**。

- **缝**：露出下面的大卡片（灰色底），本身就成了界线 —— 但它是"留白"，不是"线"
- **明度**：亮一档 → "浮在"大卡片上，而不是"切进"大卡片里

## v0.10.0 · 2026-09-15 22:35 · ⭐ 她主动发消息（新功能 B）+ 修锁死 BUG

### 新功能：她主动发消息

**这是整个项目最初那个痛点的终点。**


### 🔴 严重 BUG：数据库并发锁死（测试中发现）

测试时所有写操作 500：`sqlite3.OperationalError: database is locked`

**根因**：`db.connect()` 是**全局共享一个连接**：
```python
_conn = None
def connect():
    global _conn
    if _conn is None:
        _conn = sqlite3.connect(DB_PATH, check_same_thread=False)
    return _conn
```
`check_same_thread=False` 只是**关掉检查**，SQLite 连接对象本身不是线程安全的。
后台任务（留言 / 场景 / 承诺 / 原文索引）并发写时内部状态互相干扰，
一个事务卡住 → 全部报 locked。

**这是项目原有隐患**，之前后台写入少所以没暴露；新功能把并发推高才引爆。
（`_lock = threading.Lock()` 定义了，但**全项目从未使用过**）

**修法**：
- `connect()` 改成 **thread-local**（每线程独立连接，改动最小，全项目自动受益）
- `busy_timeout` 5s → **15s**（等锁而不是立刻失败）
- 后台任务统一走 `_run_bg()`：`run_in_executor` 的异常在 Future 里，
  外层 try 抓不到，原来只会在日志里留一句 "Future exception was never retrieved"

**实测**：30 并发写全成功、60 混合请求无错误、6 个并发 catchup 无 500

连说 3 次"明天带你去吃火锅" → 库里 **3 条** → 她会连着几天提同一件事。
**修法**：新增 `_find_similar_pending()`，用本地 embedding 查相似 pending，
命中则**升级权重 + 重置冷却**，不新建。

**⚠️ 阈值陷阱（已写进代码注释，别再踩）**
实测中文短句的 embedding 相似度：
```
"他说明天带我去吃火锅" / "他答应明天带我去吃火锅"  -> 0.998  (同一件事)
"他说明天带我去吃火锅" / "他明天带我去看电影"      -> 0.887  (不同的事！)
"他答应周末陪我去海边看日出" / "他说周末去看日出"  -> 0.813  (同一件事，换说法)
```
句子结构相同、只有动作不同时相似度虚高。
**阈值必须 ≥ 0.95** —— 定 0.85 会把"吃火锅"和"看电影"误判成同一件事。

# 设计定案

> 非代码改动，但同样别重复讨论。这些都是聊出来的结论。

- **产品定位**：文字版**生活模拟器**，不是养成游戏。核心是"让日子过得有痕迹"。不做 3D、不做回合制、NPC 10 个以内
- **第一性需求**：记忆的连续性（起源是豆包记不住东西、每天重复聊）
- **核心引擎**：**因果**，不是剧本、不是随机。你说过的话长出后果
- **只锁过去，不锁未来**：已发生的事锁定（这是记忆），未发生的事完全开放（这是自由）
- **记忆分三层**：① 规则与约定（常驻、不衰减、不走检索）② 当前状态（覆盖式）③ 事件记忆（检索、会衰减）
- **NPC 关系拓扑**：**身份是网状的，情感是星型的**（"张三是夏雪的哥哥"是静态声明，零维护成本）
- **真实感来源排序**：连续性 > 后果 > 世界自转（大部分人把精力全花在占比最小的第三项上）
- **NPC 活着靠编排，不靠模拟**：用惰性坍缩（被观察时才生成状态，生成后固化）
- **多 agent**：agent = 用什么人格生成；惰性坍缩 = 什么时候生成。两者正交。夏雪常驻，其他按需唤醒
- **模型分流**：夏雪用 DeepSeek（宽松是硬需求），NPC 日常/摘要用 agnes（免费）
- **暗号已不需要**（豆包时代的 workaround，自托管后限制消失）
