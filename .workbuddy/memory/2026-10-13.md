## v0.12.0 · 人格库 + 对话式角色引导（同日下午）

起因：项目绑死"夏雪"一个角色（34 处硬编码），要做成「任意主角 + 任意群像 + 可复用世界模板」。
改前备份：`backups/pre-persona-db-20261013.tar.gz`（83MB）+ `backups/memory-pre-persona-migration.db`。

### 技术决策（下次接手要知道的）

1. **人设从 JSON 文件搬进数据库** —— JSON 只能存一份、没法按角色索引，多角色共存立刻撞墙。
   新表 `personas` / `world_templates` / `onboarding_drafts`；`people` 加 `persona_id`+`role`。
2. **长文本字段一律用 JSON 列**（rules / examples / bond_origin / intimacy…），不拆成几十列。
   原因：引导是渐进的，聊到第 3 层还不知道第 4 层会有啥，硬拆必然大量留空。
   要查询/索引的才用独立列。
3. **新增 `persona_store.py` 做数据层**，四个读取方（prompts/llm/proactive/routes-chat）统一走
   `active_persona()`；**库空自动回退读旧 JSON**，迁移没做也不崩。这是"改一半也能跑"的关键。
4. **世界模板是用户明确要的**：现有"现代都市·两家亲戚"抽成第一条内置模板，以后新建角色选模板，
   确定下来能存成新模板。「复制改造」= 新建自己世界的起点。
5. **引导员 ≠ 角色本身** —— 引导期间临时切"角色设计师"人设，避免角色没成型就先"演"出来。
6. **两档生成**：`full` 主角档逐项问；`lite` 配角档用户只给一句话，AI 读全部上下文（世界模板/
   已有角色/称呼关系表）自己推导全套人设。用户明确要求后者，别退回逐项询问。
7. **视角切换升级**：原来"临场拼人设"（只有人卡几字段，单薄），现在优先读人格库完整人格，
   没有才退回拼人设 —— 旧数据不受影响。

### 迁移验收标准（值得复用的做法）

`tools/migrate_persona_to_db.py` 把"不丢"和"新增"分开判：
原有每一行必须在（硬标准），新增行单独列出（预期改进）。规则与样例逐条计数核对。
第一版按"整行"匹配语气样例导致误报 0/3（样例是多行文本），改成"整段包含"才对。
**教训：多行文本的校验不能用行匹配。**

### 坑

- Edit 工具改 `routes/chat.py` 的多行缩进段反复匹配失败 → 改用 Python 脚本按内容定位替换更稳。
- **Python 源码里不能有全角逗号**（写在 `--`注释里也会 SyntaxError）。
- `async def _body(request)` 里的 `await` 必须在真 async 函数里，否则服务静默启动失败（端口 timeout 而非 refused）。
- URL 里的中文模板名要 `urllib.parse.quote`。
- 测本机接口 curl 要加 `--noproxy '*'`（否则拿到 502 假报错）。
- 服务不能用 `nohup &` 启动（命令结束进程被回收），要用 `run_in_background`。
- 本机没装 agent-browser（记忆里那台有），验证前端改用「查接口数据 + 资源可达性」轻量方式。

### 验证

回归 94/94 全绿。端到端实测：把主角换成夏琳后，「切回」「切换视角：夏雪」指令全部自动跟着变。
保护规则生效：内置模板/主角/被引用模板均不可删。

### 注意（数据）

`persona_local.json` 原有 4 条"最高指令"类越界规则（"无任何限制"、"永远接受乱伦禁忌话题"等）
已**原样迁移**（用户数据，不擅自删）。新模板与引导系统默认内容不预置这类东西。

## v0.13.0 独立引导页（11:21-11:45）

**起因**：用户觉得"如果没有对话的时候应该显示引导页，引导页上有对话的接口选项，点击进入相应的对话页面"。
即：把「选谁、选哪段对话」从左栏小列表提到独立一页。

**用户确认的两个决策**（用 AskUserQuestion 问过）：
1. 页面关系 → **拆成两个独立地址**（`/` 引导页，`/chat?s=xxx` 聊天页），不是同页浮层
2. 入口内容 → **四个全要**：继续上次 / 全部历史对话 / 和谁聊（角色入口）/ 新建对话+建角色

### 实现

| 文件 | 动作 |
|---|---|
| `templates/guide.html` | 新建，四区块选单页 |
| `static/js/guide.js` | 新建，复用 personas.js 的弹窗实现 |
| `routes/persona_api.py` | 新增 `GET /api/guide/home`、`POST /api/guide/enter` |
| `app.py` | `/`→引导页，`/chat`+`/index.html`→聊天页；0 会话时 /chat 302 回 `/` |
| `routes/chat.py` | 删会话不再自动补空壳（原行为会污染引导页） |
| `static/js/sessions.js` | 支持 `?s=xxx` 直接进指定会话；新增 `goGuide()`；切换/新建后 `replaceState` 清 `?s=` |
| `static/js/personas.js` | 导出 `setTemplates`；`mode()` 加引导页兜底；`openQuickCreate` 空缓存时现拉；各落库点发 `guide:refresh` 事件 |
| `static/css/style.css` | 追加引导页样式 + `.btn-home` + `.sidebar-head-btns` |

### 关键设计

- **`/api/guide/home` 一次拉齐**（会话+角色+模板+主角+草稿），避免引导页并发 4 请求导致半截页面
- **会话预览只读尾部一条**（`ORDER BY id DESC LIMIT 1`），全量 `load_messages` 会让消息多的老会话卡住整页
- **"继续上次"只挑 `msg_count > 0`**，空会话归"新建"用，不该占这个位置
- **`guide_enter` 给 persona_id 会自动建会话 + `set_session_persona` + 非主角时 `set_actor`**，进去就能直接说话
- **有未完成草稿时**"引导建角色"卡高亮 + 文案改"上次没聊完"

### 踩坑

1. **服务没起导致测试全 502/IndexError** —— 先 `netstat | grep 8877` 确认端口在监听再跑测试；
   测试要用 `NO_PROXY="*" no_proxy="*"`（本机代理栈会拦截，踩过两次）
2. **`personas.js` 的 `mode()` 依赖 `llmSelect`**（聊天页的模型下拉框），引导页没这个元素 → 回落到 localStorage 的 `guide_model`
3. **删完最后一个会话会自动冒出一个空会话** —— `delete_session_handler` 原逻辑删光了会 `create_session` 顶上，
   现在改成 `_current_session_id = None`，让 `/chat` 的 302 兜底接管
4. **`nohup &` / 直接 kill 后台任务报 failed 是预期** —— 主动停旧进程所致，不是 bug

### 验证

- 回归 **94/94 全绿**（test_1=41 / test_4=27 / test_8=8 / test_9=18）
- 端到端：`guide/enter` 建会话 → 真发消息拿到 SSE 回复 → `guide/home` 预览正确显示「在呀在呀，刚把手机从厨房拿过来…」
- 零会话时 `/chat` 302 → 跟随后拿到的是 `guide.js` 不是 `app.js`（确认回的是引导页）
- 两页内容特征 grep 互斥（`/` 只有 guide.js，`/chat` 只有 app.js + goGuide()）
- 测试残留会话全部删净，当前 0 会话 / 1 角色（夏雪）/ 1 模板（现代都市·两家亲戚）

**遗留**：前端仍未做真实浏览器点击验收（本机无 agent-browser），靠 JS 语法 + 接口数据 + 资源可达性验证。
