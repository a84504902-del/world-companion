## v0.13.1 提示词配置化（20:54-21:20）

**起因**：用户说"越界内容不需要清除，现在继续优化这个项目"。
上一轮体检只报了 `prompts.json` 的 `state_card` 硬编码「夏雪」这一个问题，
用户明确表示人格库里的越界内容（3 条「最高指令」+ 2 条性描写要求）**保留不动**。

### 核心发现：`get_prompt` 是 json 优先，导致代码里的动态兜底是死代码

这是本轮最重要的认知，写下来防止以后再踩：

```python
get_prompt("state_card", <代码里那份动态文案>)
             ↑prompts.json 有同名键 → 用 json 的，代码里那份【永远不执行】
```

`routes/chat.py` 里其实早就写了一份动态文案（用 `_get_protagonist_name()` 取当前主角），
但因为 `prompts.json` 里有 `state_card` 键，那份动态文案从没被执行过。
真正跑的一直是 json 里的硬编码版 → **换任何角色，状态卡都按夏雪的底色纠正别人**。

而且「大方、主动、坦率」这三个词本身也是夏雪专属的——
就算把名字改动态，性格描述还是错的。所以修法不是替换名字，是**连性格一起动态化**。

### 修了 4 件事

| 问题 | 修法 |
|---|---|
| `state_card` 硬编码角色名 + 硬编码性格 | 占位符 `{{PROTAGONIST}}` `{{TRAITS}}`，值由新增的 `persona_vars()` 从 personas 表取 |
| 改 prompts.json 必须重启服务 | `_load_prompts` / `load_anchor` 按文件 mtime 自动重载 |
| `summary_detail` 死配置 | `summarize_handler` 把同样文案硬编码在代码里 → 改走配置层 |
| `summary` 死配置 | 按用户选择接到导出功能：导出时带剧情概要 |

### 占位符机制

- `get_prompt(key, default, **variables)` 支持替换，没传的占位符自动清空
  （不会出现把 `{{FOO}}` 原样发给模型的情况）
- 可用变量：`{{PROTAGONIST}}` `{{TRAITS}}` `{{USER_NAME}}` `{{RELATION}}`
  全部来自 `personas` 表当前主角，**换角色自动跟随**

### 导出带概要（新增功能）

之前导出的 md/txt 只是一堆干巴巴的回复，隔几天看根本想不起来在聊什么。

- 有现成摘要（`summaries` 表）→ 直接复用，不花 LLM
- 消息不足 4 条 → 不生成（没什么可概括的）
- 否则现场生成简版，用 `asyncio.to_thread` 丢线程池（**不要在 async 函数里直接调阻塞 LLM**）
- 失败静默降级，不阻断下载
- 三种格式：md 用 `> **剧情概要**`、txt 用 `【剧情概要】`、json 加 `summary` 字段

### 新增 `tools/check_prompts.py`

把这三类只能靠人肉发现的问题变成可自动跑：
1. **死配置**：json 有键但代码没 `get_prompt` → 改了没效果
2. **硬编码角色名**：文案里写死人名（角色名从人格库动态取，换角色照样能查）
3. **占位符未接线**：json 用了 `{{X}}` 但调用方没传

**验证方式（重要）**：故意注入硬编码 + 死配置 → 精准报出 2 项；恢复 → 全绿。
不自检的检查脚本可能是个永远说"通过"的假检查，必须反向验证过才算数。

### 验证

- 回归 **94/94 全绿**（test_1=41 / test_4=27 / test_8=8 / test_9=18）
- 换角色：内存注入「夏琳/高冷、毒舌、慢热」→ 渲染出「夏琳的性格底色是高冷、毒舌、慢热」，无夏雪残留
- 热重载：改 json → 立即生效；还原 → 立即还原
- 导出端到端：真聊 4 轮 → 三种格式都正确带出概要
- 边界：空会话导出不报错无概要；2 条消息不触发生成

### 踩坑

1. **测试前先确认服务在监听**：`netstat -ano | grep 8877`，否则测试全 502
2. **测试必须带 `NO_PROXY="*" no_proxy="*"`**：本机代理栈会拦截，踩过三次了
3. **Edit 时我打错字导致 old_string 不匹配**（"专有人名"写成"专有名名"）→ 重新 Read 再改
4. **改 async 函数时手滑删掉了 `try:`** → 编译虽然过了但逻辑坏了，
   插入新函数时要确认缩进结构（py_compile 抓不到这种）

## v0.13.2 换中文 embedding 模型（21:10-21:30）

**起因**：用户问「记忆功能现在有2个命令，是同样的作用吗」。

**用户决策**：
- 越界内容不删（上一轮问过了）
- 阈值方案 → 同意改
- 换模型 → 选了「换中文模型（推荐）」

### ★ 最重要的发现：这类 bug 不报错，只是悄悄变差

原来模型是 `all-MiniLM-L6-v2`（**纯英文** BERT 词表）。分词实测：

```
「我讨厌香菜」→ ['我','[UNK]','[UNK]','香','[UNK]']
「喜欢你」    → ['[UNK]','[UNK]','[UNK]']      ← 一个字都不认得
```

**中文丢失率 70.4%**。诡异现象：不同问句跟同一条记忆算出**完全相同**的分数
（「我对芒果过敏」←「你是谁」/「吃了吗」/「喜欢你」全是 0.6103）。

**教训**：这种故障模式最危险——**服务正常、接口正常、不报错**，只是检索不准。
不主动打印 `[UNK]` 占比根本发现不了。以后遇到"检索效果怪怪的"，
第一件事是验证模型对该语言的根本支持，别急着调阈值。

### 调阈值救不回来（正负样本重叠）

30 正样本 × 110 负样本扫描：

| 阈值 | 召回 | 误召 |
|---|---|---|
| 0.30（原） | 100% | **93.6%** |
| 0.55 | 66.7% | 35.5% |
| 0.70 | 43.3% | 4.5% |

有负样本（`明天要加班到很晚 ← 今天天气怎么样` = 0.7834）比大多数正样本还高。
**调阈值是治标，换模型才是治本**。

### 换模型结果

`all-MiniLM-L6-v2`(384维英文) → `BAAI/bge-small-zh-v1.5`(512维中文)

| | 旧 | 新 |
|---|---|---|
| 中文丢失率 | 70.4% | **0%** |
| 负样本均值 | 0.5115 | 0.3429 |
| 0.55召回/误召 | 66.7%/35.5% | **90.6%/1.6%** |

阈值 0.3 → `MEMORY_MIN_SCORE = 0.55`（190 负样本实测定的，注释里记了依据）。

### 防复发的三道防线

1. **模型路径改候选列表**：原来只有「总线 embedding」一个目录，换模型必须原地覆盖
   ——但总线是多项目共享的，动了影响别的项目。
   现在：`EMBEDDING_MODEL_PATH` 环境变量 → `embedding-zh` → `embedding` → 项目本地 → HF 名字。
   **兜底也从英文模型换成中文模型**（原来兜底英文 = 悄悄退化成坏的）。
2. **`check_chinese_support()`**：直接算 `[UNK]` 占比给判断，一眼看出模型认不认中文
3. **`tools/rebuild_vectors.py`**：`--check` 体检 / `--dry-run` 预演 / 默认重建（自动备份）
   维度不匹配会明确报：`维度 [384] vs 当前模型 512 → 必须重建`

### 踩坑

1. **hf-mirror 下载 401**：`snapshot_download` 报 `CAS Client Error: 401 Unauthorized`
   → **加 `HF_HUB_DISABLE_XET=1`** 走传统下载，立刻成功（配置 json 其实已下好，只缺权重）
2. **`get_sentence_embedding_dimension` 有 FutureWarning** → 新版改名
   `get_embedding_dimension`，用 `getattr` 两个名字都试
3. **备份大目录用 `cp -r`** 没问题（87MB 很快）

### 验证

- 回归 **94/94 全绿**
- 端到端：存 2 条记忆，问 8 个问题 → 该召回的准召，5 个无关问题（你几岁/在吗/
  今天天气怎么样/喜欢你/帮我看看代码）全不误召
- 服务启动无 warning
- 测试数据全清（31 块原文块是用户真实对话的，保留）

### 已知取舍（写下来免得以后当成 bug 查）

「豆豆最近怎么样了」(0.5308) 压线没召回，「豆豆呢」(0.6570)/「猫在干嘛」(0.5744) 能召回。
这是 0.55 的正常边界。**不要再降阈值**——190 负样本实测 0.55 误召已只1.6%，
再低就开始误召。

### 顺带说明：原文块检索没动

`retrieve_chunks` 阈值仍是 0.35。它跟记忆检索不是一回事——
原文块是**真实对话原文**，误召只是多塞点上下文，不会像错误记忆把 AI 带偏。
实测 0.35 下对无关问题也召回片段，但代价可接受。

## v0.14.0 引导改成「建新对话」（22:30-23:00）

**起因**：用户跑完引导后说——
> 「我引导我设定了主角，就是个单纯的角色，这个引导建角色不是设定一个
> 新对话的角色设定啊，我有点不明白了」

追问后澄清真实意图：
> 「我的想法不是建一个角色，是建一个新对话，然后设定对话里的人物，
> 这样一步一步设定好，我就能开始玩角色扮演了」

### ★ 诊断：「建角色」和「开新对话」被揉成了一件事

原五层里有两层是"你和她要多亲密"（关系起点问阶段、互动质感问"亲密到哪一步"）
——那是**对话运营**，不是人物属性。再加「设为主角」是全局唯一开关，
勾一下夏雪立刻降级 → 用户感觉"建角色=决定我现在跟谁说话"。
而且旧实现写死了「她」，建男性角色也照问"亲密到哪一步"。

用户三个决定（AskUserQuestion）：
1. 建角色边界 → 自定义回答"我是不明白这样建角色有什么用，都是单独的角色"
2. 建完是否自动开对话 → **不自动开**
3. 夏雪被降级 → **恢复**

### 改动

| 项 | 原来 | 现在 |
|---|---|---|
| 引导产出 | 孤立人设，没处用 | **可玩的对话**（人设+会话），引导页点一下开聊 |
| 第2层 | 关系起点 | **你是谁**（用户在故事里的身份） |
| 第4层 | 互动质感（亲密到哪一步） | 关系与互动（怎么认识、希望对方怎么对用户） |
| 设为主角 | 建角色时勾选，夏雪降级 | **取消**，去角色库手动切 |
| 世界归属 | world_template_id 常为空 | 没选就**继承主角世界** |
| 重复建 | 点两次建两个 | 同名查重拒绝 |
| 同名覆盖 | 撞名绑上"用户本人"行 | 识别 role∈('','user','self') 跳过绑定 |
| 会话视角 | 进去还按夏雪说话 | 建会话时 `set_actor(name)` |

### ⚠️★ 我犯的错：用 `cp` 备份 SQLite（WAL 模式）
